## Этап 1. Фактическая архитектура

Админка уже написана на React 18 и Telegram UI. `worker.mjs` проверяет подписанный
Telegram initData основного бота и ID владельца до доступа к D1. Публичные «Находки»
используют другой бот/сеанс. Изменения админки не требуют замены backend или нового бота.

| Область | Существует и работает | Требует улучшения / отсутствует |
|---|---|---|
| Главная | Статус канала, очередь, последние/следующие операции, пауза, защищённые команды | Сводка за сутки, реакции и обучение, понятные ссылки на основные настройки |
| Поиск | `native_scheduler.mjs`: реальный список `scheduler_policy.data.queries`, курсор, одна тема за запуск; индексная дедупликация, проверка WB-карточек/фото; глобальная аренда, persisted backoff | Нет владельческого редактора списка, приоритетов, отключения каждой фразы, истории запусков и выгрузки; UI показывает только последний запуск |
| Источник WB | Рабочие storefront search/card endpoints; `wb_source.mjs` — узкий авторизованный адаптер существующего Python scanner | Сохранить источник. Новые интерфейсные действия должны использовать общие аренду/backoff, без параллельного парсера |
| Подбор | Цена сверху, рейтинг, отзывы, blocked_words, blacklist, disabled_topics в D1; Legacy ограничивает повторы тем/названий | Нет экрана политики, нижней цены, списков брендов/категорий, управляемого распределения; подтверждённые стили доступны не для всех товаров |
| Расписание | Интервал, конкретные часы, дни, тихие часы, часовой пояс, отдельный поиск; серверная валидация/CAS; явное сохранение | Предпросмотр только одного поста, нет 60-минутной кнопки/суточной оценки/журнала и восстановления |
| Очередь | Шесть карточек/страница, фото/цена, выбор конкретного товара, skip/delete, повторная проверка цены и защита дублей | Поиск/фильтры, опубликованные, рейтинг/отзывы/время и ясная готовность |
| Обучение | Legacy, River SHADOW, реальные события/текущие реакции, сравнение и пороги данных | Отделить временные события от уникальных наблюдений, честно показать неподключённый Vision; не переносить PR№7 |
| Диагностика | Cron, источник WB, Telegram-настройка, webhook timestamp, очереди, D1 ledger/backoff | История ошибок/восстановлений, сроки и понятные состояния неизвестных проверок |
| Управление | Идемпотентные команды, revision conflict, initData/owner guards, read/write budgets | Единый ограниченный журнал конфигураций и безопасное восстановление с текущей revision |

Рабочие таблицы: `scheduler_config` (расписание/revision/status), `scheduler_policy`
(политика и реальные фразы), `scheduler_inventory`, `scheduler_deliveries/posts`,
`scheduler_leases/claims/requests/actions`, `learning_*`, `reaction_*`, `visual_*`,
`worker_read_budget`. Новые редакторы используют их, дополнительные таблицы нужны
только для истории запросов и аудита изменений. Полный сброс/перенос D1 исключён.

Порядок публикации сейчас: исключение известных/заявленных товаров и повторов
нормализованного названия; максимум восемь публикаций одной поисковой темы за сутки;
фиксированное чередование аудиторий/аксессуаров; преимущество проверенным фото и смене
последней темы. River только сравнивает свой выбор в SHADOW. «Очередь» — список
кандидатов, не обещание точного FIFO.

## Реальные данные и пробел наблюдаемости

Production-настройки проверяются через существующий защищённый read-only endpoint
`/api/scheduler/admin`, а не через локальный settings.json. Действующий backend пока
не выдаёт весь `scheduler_policy` через API. Поэтому полное количество/список реальных
фраз нельзя подтверждать по файлу или примерам. Доступны последние реальные поисковые
квитанции из D1; полный новый экран будет читать список непосредственно из D1.
Исторические показатели отдельных фраз до включения журналирования — «Нет данных».

Свежая [production-квитанция](https://github.com/22savage22/wb-deals-bot/actions/runs/38041179075):
интервал30, поиск20, запас88/100, timezone Europe/Moscow, revision1791202121046,
автопост2781 и последующий автоматический Cron. Последняя подтверждённая фраза —
**«худи мужское»**: найдено100, новых кандидатов1, проверен1, добавлен1 (nmId498913016).
Последняя цена614 ₽, карточка «Худи спортивное». Это последняя квитанция, не полный
список production-фраз. River SHADOW, trained_events147; текущие голоса48/99/0
(лайки/дизлайки/купил), Visual disabled. Значения — снимок, а не вечные настройки.

## Исследование готовых решений

Проверены README, структура, GitHub metadata и лицензии 10.10.2026:

- [WBLens](https://github.com/ordinartsev2000/WBLens): MIT, последнее изменение
  24.08.2026. Python/aiogram/aiohttp/RapidFuzz; полезна идея отделять сходство названия
  от обязательного совпадения типа, размера и количества в комплекте. Прямой перенос
  Python-бота в Worker не нужен. Реализовать небольшую собственную функцию сравнения
  и предложения уточняющих фраз; не заявлять эвристическое сходство гарантией аналога.
- [upsalesvideo/wb-parser](https://github.com/upsalesvideo/wb-parser): последнее изменение
  08.05.2026, лицензия в GitHub metadata/корне не заявлена. Python web-сервис с
  поиском/артикулом/экспортом. Код не копировать; существующий источник уже решает
  получение карточек, а экспорт можно реализовать в интерфейсе без зависимости.
- [Wildberries-Parser-Workspace](https://github.com/alextrader2007/Wildberries-Parser-Workspace):
  последнее изменение 27.05.2026, лицензия в metadata/корне не заявлена. Express,
  Python/Selenium/Chrome, CORS-прокси, Gemini. Этот стек и обходы не подходят ограничениям
  проекта; зависимости/скрипты не устанавливать и код не копировать.

Использовать уже установленный `@telegram-apps/telegram-ui` с React: MIT подтверждена
lockfile для Telegram UI, React и React DOM. Дополнительная библиотека графиков не нужна:
карточки, native form controls и небольшие SVG достаточно легки для мобильной админки.

## Последовательные этапы и критерии приёмки

1. **Аудит:** эта карта, live production receipt и отдельный Draft PR. Никаких изменений D1.
2. **Поисковые фразы:** чтение всех из D1, редактор/включение/архив/приоритет, CAS и
   экспорт/импорт с предпросмотром; история реальных запусков, товары/ошибки, ручная
   проверка через общую аренду/backoff. Тесты запрета подписчику, конфликтов, отката,
   лимитов и отсутствия записи настроек на GET.
3. **Подбор и сходство:** серверная политика/фильтры/ограниченное разнообразие с
   перераспределением при дефиците; объяснимое сравнение имеющихся товаров, подсказки
   запросов только по явному принятию. Неизвестные признаки не превращать в факты.
4. **Расписание и очередь:** несколько будущих времён, фактические/ожидаемые суточные
   показатели, поиск и история карточек; аудит и CAS-восстановление. Применение только
   по «Сохранить», исходный production-интервал30 не менять.
5. **Обучение/диагностика/дизайн:** данные и отсутствующие возможности обозначать
   честно, журнал ошибок/восстановлений, доступные мобильные элементы, светлая/тёмная
   тема, отсутствие двойных действий. Visual PR№7 не переносить, River не активировать.

После каждого этапа — тесты и commit, обновление AI-Brain. Preview должен работать
с изолированным хранилищем, без Telegram отправок/production Cron и доступа к основной
D1. Локальная проверка реального backend допустима как первый preview; удалённый
Cloudflare staging и ручная приёмка владельцем остаются отдельными release gates.
Для локальных сценариев явно маркировать примеры и исходную дату снимка production.

Ресурсы: сохранить существующие бюджеты Worker, индексы, курсоры, ограниченную историю,
один WB-запрос через общий limiter и отсутствие запросов на каждый рендер. Измерить
число D1 операций в сценариях; локальные SQLite оценки не выдавать за биллинг D1.
Никаких платных сервисов и новых AI вызовов для разработки этой админки.

## Этап 2 — реализован, 2026-10-10

Все запросы читаются из фактической scheduler_policy; редактор, приоритеты, архив,
импорт с предварительным просмотром и экспорт сохраняются только явно, с CAS.
История ограничена 500 поисками / 100 изменениями; прежняя статистика неизвестна.
Ручная проверка использует общий lease и backoff, не добавляет товары в публикации.
154 backend-теста прошли; сборка успешна. Дополнительный HTTP-тест preview прошёл:
реальное сохранение, запрет поддельного Host/Origin, запрет публикации и Cron.
Локальный preview использует отдельную SQLite, синтетическую авторизацию и один
публичный товар из снимка; внешние WB/Telegram/AI отключены. HTTP доступ подтверждён.
Computer Use получил один timeout; визуальная приёмка не подтверждена. Причина
первоначальной недоступности loopback — ограничения Windows sandbox, сервер
запущен отдельным разрешённым процессом. Production не изменён.

## Этап 3 — реализован, 2026-10-10
