# Настройки расписания

Telegram: `/schedule` или **Меню → Расписание**. Mini App: **Профиль → Админка**.

Настройки хранятся в существующей Cloudflare D1, отдельно от каталога и секретов.
Изменения используют revision/CAS: параллельное редактирование не затирает
сохранённые чужие поля. Выключение ПК и перезапуск GitHub Actions не сбрасывают их.

По умолчанию публикации включены: каждые 10 минут, ежедневно, Europe/Moscow,
без тихих часов и случайного смещения. Поиск каждые 20 минут; при запасе ниже
100 товаров — приоритетный поиск не чаще одного раза за 5 минут.

Можно выбрать произвольный интервал, конкретные часы, дни недели, ночную тишину,
часовой пояс, отдельную частоту поиска и запас 1–300. Пауза постов не останавливает
поиск и не очищает очередь. Товары хранятся до 72 часов; цена и фото выбранной
карточки проверяются перед отправкой. Посты ограничены минимальным перерывом
5 минут, часовым/суточным лимитами. «Пост сейчас» обходит паузу/окно времени,
но не защиту и лимиты. Разовая команда выполняется один раз ближайшей сессией.

## Исполнение

Один частый триггер `deals.yml` запускает ограниченную по времени сессию
`scheduler.py`; раз в 25 секунд проверяется сохранённое расписание. Поиск выполняет
отдельный `scanner.yml`, только когда он нужен. Cron — механизм пробуждения,
не расписание публикаций. GitHub может задерживать старт и терять cron-события;
это не гарантированный сервис точного времени. Пропущенные точные часы не
догоняются пачкой. Админка показывает heartbeat и реальные следующие времена.

D1 lease сериализует автопостинг и ручные публикации. Карточка резервируется
атомарно перед Telegram; успешный результат фиксируется в журнале. Если Telegram
принял отправку, но ответ потерялся, nmId не отправляется повторно автоматически:
предпочтительнее пропустить неопределённый результат, чем создать дубликат.
Недоступность D1 закрывает отправку (fail-closed), не включает небезопасный fallback.

Для новой логики используется существующий `MINIAPP_SYNC_KEY`, новые секреты не
нужны. Существующий источник WB и настройки Telegram не заменяются. Исторические
941 артикула не подключаются как основной поиск.

## Безопасный порядок включения

1. Проверить Python/Node тесты.
2. Обновить существующий Worker, наследуя все bindings и secrets.
3. Проверить `/api/scheduler/config` и runtime с действующим sync key из GitHub.
4. Только после этого перенести изменения workflows в main.
5. Проверить новую карточку, очередь, успешный Telegram-пост, heartbeat и включённые
   публикации/поиск. Не считать локальные тесты подтверждением production.

Изменение расписания через админку не требует commit, deploy, правок YAML/.env.

# Cloudflare transition

The normal deployment/clock target is now described in
`cloudflare-builds-cron.md`: official Workers Builds, a native minute Cron and
existing D1, with bounded Python execution jobs. The legacy runner above stays
available for recovery until the managed path passes its live end-to-end gate.
