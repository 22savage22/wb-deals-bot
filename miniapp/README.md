# Находки — Telegram Mini App

## Текущее размещение

Мини-приложение развёрнуто на Cloudflare Workers + D1:
https://wb-finds-miniapp.valeramyakishev000.workers.dev .
Бот: https://t.me/WbPodborr_bot — меню «Мои находки».
Инструкции эксплуатации и ограничения бесплатного тарифа: [Cloudflare](cloudflare/README.md).
Ниже также сохранён альтернативный вариант запуска Flask/Docker.

Первая бесплатная версия: каталог, личные сохранения и папки, отметка «Уже есть»,
подбор до трёх образов, замена вещей, сохранение комплектов, настройки бюджета.
Владелец может исправлять тип вещи, аудиторию и скрывать товары в каталоге.
Платёжных экранов и искусственных ограничений бесплатной версии нет.

## Как устроен подбор

Подбор использует реальные товары: платье + обувь либо верх + низ + обувь,
затем сумку и украшения, если позволяет бюджет. Основная вещь сохраняется
при замене. Уже имеющиеся сохранённые вещи стоят 0 в бюджете новых покупок.
Цена кандидата должна быть проверена не более 48 часов назад. Неизвестные
размеры, цвета, наличие и посадка не выдаются за проверенные. Повод влияет
на приоритет названий и типов вещей; это ещё не персональный ИИ-стилист.
Когда хватает товаров только на один образ, показывается один, а не копии.
«Заменить» исключает вещь и пересобирает варианты вокруг основной вещи.
Покупка осуществляется на WB по отдельным ссылкам: интеграции с корзиной WB нет.

## Хостинг

GitHub хранит код и выполняет тесты/синхронизацию. GitHub Pages не запускает
Python и не хранит личные данные; GitHub Actions не используется как сервер.
Приложение запускается на Linux-сервере с Docker Compose и постоянным томом.
Один экземпляр приложения, SQLite в режиме WAL. Для нескольких экземпляров
понадобится общая серверная БД. Подключение хостинга и создание бота выполняются
до включения кнопок в канале. Бот канала и второй бот используют разные токены.

1. Создать второго бота через @BotFather. Не публиковать его токен в GitHub.
2. На сервере клонировать **этот же репозиторий** и скопировать
   `miniapp/env.example` в `.env.miniapp` (файл игнорируется Git).
3. Заполнить `MINIAPP_BOT_TOKEN`, `MINIAPP_BOT_USERNAME` (без @),
   `MINIAPP_ADMIN_ID` (числовой Telegram ID владельца), `MINIAPP_DOMAIN`
   (домен без https://), `MINIAPP_SYNC_KEY` (случайная строка от 32 символов).
   Домен должен указывать на сервер; открыть порты 80 и 443.
4. `docker compose up -d --build`. Caddy получает HTTPS-сертификат,
   SQLite хранится в постоянном томе `app-data`.
5. Проверить `https://ДОМЕН/api/health`: `ok` и `configured` должны быть true.
6. В BotFather: `/mybots` → второй бот → Bot Settings → Configure Mini App →
   Enable Mini App, задать `https://ДОМЕН/`. Также можно настроить Menu Button.
   Приложение работает через Main Mini App; отдельный poller второго бота не нужен.
7. В GitHub → Settings → Secrets and variables → Actions добавить:
   - secret `MINIAPP_SYNC_KEY`: тот же ключ, что на сервере;
   - variable `MINIAPP_API_URL`: `https://ДОМЕН`;
   - variable `MINIAPP_BOT_USERNAME`: имя второго бота без @.
   Токен второго бота в Actions не нужен.
8. Запустить `miniapp-catalog.yml` вручную и проверить каталог приложения.
   Он наполняет отдельный каталог для образов (включая обувь) каждые 6 часов,
   независимо от ценовых лимитов канала. Сохраняет каждый проверенный товар сразу.
9. Пройти проверку двумя Telegram-аккаунтами: разные сохранения, подбор,
   замена, сохранение образа, перезапуск сервера без потери данных.
10. Только после проверки установить variable `MINIAPP_ENABLED=1`.
    Новые посты получат «Сохранить» и «Собрать образ». Старые посты не редактируются.

`deals.yml` передаёт каталог после публикации, `scanner.yml` — после сканирования.
`miniapp-catalog.yml` дополнительно ищет и проверяет фотографии вещей для образов.
Отправляются только явно разрешённые поля товаров; Telegram ID, голоса и настройки
бота не передаются. Фото новых публикаций используют URL, успешно проверенный
существующим загрузчиком WB. Лента показывает только товары с фото; ошибки загрузки
скрывают карточку из ленты, но не удаляют её из личных сохранений. Старые товары
постепенно проходят `miniapp.backfill`: до 24 кандидатов за запуск с ротацией
категорий, повторной проверкой цены и настоящего фото. Непроверенные цены не
получают новую дату. Недоступность WB не очищает существующий каталог.
Старые лайки не переносятся: в них нет достаточных данных для восстановления избранного.

## Обновление и восстановление

Обновление сервера: `git pull --ff-only` и `docker compose up -d --build`.
Не выполнять `docker compose down -v`: это удалит постоянные тома.
Для резервной копии SQLite использовать SQLite backup API (файл БД нельзя
копировать отдельно от WAL во время записи). Хранить резервные копии вне Git.
Данные конкретного пользователя удаляются кнопкой в профиле.
При отключении сервера убрать `MINIAPP_ENABLED`; бот канала продолжит работу.
Публичный каталог не содержит личных данных. Личные API требуют Telegram initData
с проверкой HMAC и возраста до 1 часа. После часа приложение нужно открыть заново.
ID пользователя из тела запроса не принимается. Администратор проверяется на сервере.

## Разработка и тесты

```
pip install -r requirements.txt -r miniapp/requirements.txt
python -m miniapp.app
python tests/run_all.py
python -m unittest discover -s tests -p 'test_miniapp*.py' -v
node --check miniapp/static/app.js
node --test miniapp/cloudflare/*.test.mjs
```

Сервер разработки слушает только 127.0.0.1:8080. Без Telegram можно просматривать
каталог, но нельзя сохранять товары или делать персональные запросы.
Тесты создают временную БД внутри `.test-tmp/` проекта, настоящие токены не нужны.

## Лента и подбор образов

Первый вход предлагает необязательные аудиторию, бюджет одной вещи и интересы.
Эти несекретные фильтры хранятся только в localStorage устройства; при запрете
хранилища интерфейс продолжает работать. Их можно изменить над поиском.
Режим «Для вдохновения» чередует типы вещей. Карточки добавляются порциями по 24,
без пересоздания уже показанных изображений; после четырёх автоматических порций
остаётся кнопка продолжения. Анимации отключаются при prefers-reduced-motion.

Образы требуют фото и цены не старше 48 часов. Подбор по описаниям исключает
детские, домашние и неподходящие вещи, явные конфликты аудитории, сезона, стиля
и нескольких известных акцентных цветов. Это не визуальная AI-оценка: неизвестные
цвета, размеры и посадку нужно проверять на WB. Коллаж показывает реальные карточки
вещей, а не сгенерированную примерку. Лучше пустой результат, чем неполный комплект.

Для существующего Cloudflare Worker использовать действие `update` в
`miniapp.cloudflare_deploy`: оно наследует текущие bindings в строгом режиме,
обновляет только код/статику и не меняет базу, webhook или секреты. Действие `deploy`
предназначено для первоначального подключения, не для обычного обновления дизайна.
